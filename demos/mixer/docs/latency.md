# Click-to-picture latency

Command acknowledgment and `mixer.status` settlement do not measure when the
viewer sees the picture. The browser test timestamps the TUI's actual
`mousedown`, then reads the source/frame barcode in each presented video frame.
It measures to `requestVideoFrameCallback().expectedDisplayTime` for the first
verified destination frame. Both timestamps use the browser performance clock.

## Initial baseline

| Measurement | Result |
| --- | ---: |
| Warm cuts, fullscreen ↔ 4-box | 11 samples |
| Median | 190.0 ms |
| 95th percentile / worst | 207.3 ms |
| Minimum | 140.1 ms |

This development baseline used 16 numbered H.264 inputs, 60 fps portrait output,
a Tesla T4 with 16 vCPUs, H.264 NVENC P6/ultra-low-latency at 3 Mbit/s, no
B-frames or lookahead, and Chromium 148 on the same host. The hidden destination
scene was prewarmed before each timed CUT. It is not a cold-switch, fade or
media-wipe measurement. [Raw samples](latency-baseline.json) include pixel-read
overhead, which reached 19.6 ms in this initial probe.

These are browser presentation estimates, not physical monitor measurements.
They exclude Internet transport and display scan-out. The browser's timestamp
is best effort, and the probe itself adds work. Compare before/after runs with
the same browser, layout, load and probe; do not treat this baseline as a latency
guarantee. See the [video-frame callback specification](https://wicg.github.io/video-rvfc/).

## Reproduce

Use the clips generated by `tests/frame_codes.py`, a running mixer, its ttyd
browser TUI, and the Janus player. Keep debugging ports on loopback; SSH may
forward them when measuring a browser on another host. Run Chromium with remote
debugging enabled and open the Janus player. Node.js 22 or newer runs the probe
without additional packages:

```sh
node demos/mixer/tests/measure_click_latency.cjs \
  http://127.0.0.1:9222 \
  http://127.0.0.1:8080/ \
  http://127.0.0.1:7681/ \
  /tmp/click-latency.json
```

The probe places video and TUI together in a visible browser page so hiding the
video in a background tab cannot stop presentation callbacks. It requires
advancing, readable video and fails if the destination never appears. It saves
raw timings, errors and a calibration screenshot beside the result JSON.

The default click coordinates assume a 1600×1000 TUI at 15px terminal font.
Fonts change terminal cell dimensions: inspect the screenshot and, if necessary,
append three `x,y` arguments for Fullscreen, 4-box and CUT, relative to the TUI
iframe. Direct mode must be OFF. This intentionally changes the live program.
For the initial baseline's font metrics, the coordinates were:

```sh
# Append after the result filename:
140,455 565,455 140,677
```

For a network measurement, run the browser at the viewer's location. Record
packet loss, freezes, browser frame rate and network RTT alongside the latency;
keep failed samples visible. Fade and media-wipe onset/completion require
separate pixel checks and are not covered by this CUT probe.
