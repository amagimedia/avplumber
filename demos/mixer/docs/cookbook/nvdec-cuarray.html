NVDEC arrays without a staging copy

The mixer samples NVDEC's decoded CUDA arrays directly. At the same 192 inputs and 20 outputs, whole-GPU memory fell from 20.65 to 15.77 GiB: 4.88 GiB saved, or 23.7%. The recovered room supports 28 encoded outputs, with the decoded queues still at three frames and AUX latency still at 80 ms.

Status: Opt-in, measured on L4

The idea

The linear CUDA baseline keeps decoded output images separately from NVDEC's decode surfaces. The new path registers a fixed pool of CUDA arrays with NVDEC and publishes references to those same arrays. Matching normalization forwards the handle; the compositor reads the planes through textures while rendering its output canvas. There is no intermediate decoded-image copy.

Measured gain

The workload has 120 independent HEVC 1080p25 clips, 32 raw inputs and 40 DMA-BUF browser inputs. The 20-output runs use identical scenes, resolutions, rates and encoder settings. Twenty outputs means two program renditions, two monitors and 16 extra AUX buses; 28 adds eight AUX buses.

A fresh 28-output container also passed a five-minute quiet capture: all 120 decoders and 28 encoders advanced at 25.00–25.01 fps, with zero output drops, missed deadlines or overflows. A separate two-minute AUX page-switch repeat was clean. Cut/fade/wipe stress completed 136 cuts, 57 fades and 52 wipes with zero missed program deadlines. The full report retains rejected runs and validation limits, including an earlier scheduling capture with three output drops.

These are tested configurations, not a universal capacity ceiling. A 32-output attempt hit the existing downstream-key fanout limit before a valid run; it did not establish a VRAM or NVENC limit.

Fixed surfaces are separate from queues

extra_hw_frames adds application headroom to the codec's reference and working surfaces. It does not change the decoded edge's capacity or the AUX deadline. Queues and independently timed outputs hold references to decoded pictures; they share the image storage but can keep different pictures alive.

The pool is allocated up front and never grows or silently switches to copying. Other bitstreams can need a different base count. Validate decoder progress as well as output deadlines: a stalled input can leave downstream outputs repeating its last picture. The earlier one-frame queue proposal was not selected; this optimization keeps all three decoded queue slots.

Since this measurement

Tone mapping reads arrays too. tonemap_cuda now reads arrays in its colour, depth and chroma conversion kernel and writes the final linear output, with no intermediate copy of the input (patch 0016 of the FFmpeg series). The format conversion that scale_cuda rejects for arrays therefore has a path. Where a source's declared colour already matches the canvas and no storage is requested, the mixer's conversion graph is setparams alone, so the frame reaches the compositor as the array NVDEC wrote: a 4:2:2 HDR compositor samples 4:2:0 arrays itself. The change ships a pixel comparison of array against linear inputs; what it saves in memory or CPU was not measured on its own.

Output ceilings from full-scene sweeps. The 28 outputs above passed a quiet capture and a cut, fade and wipe stress. Later sweeps on an L4 cut through all 256 scenes of the 192-input SDR show at 25 fps: 30 outputs had passed a six-cut probe and then failed the sweep, with 693 missed deadlines, 856 AUX output drops and NVENC at 100 % (p95); at 26 outputs the first sweep had one AUX drop and the repeat none. The sweep table has no run at 28 outputs. Setup now admits 26 encoded outputs at 25 and 30 fps on an SDR canvas and 22 at 50 and 60, programs and the reserved clean feed included. A show whose 96 decodes were all HLG ran out of memory at encoder start, and the automatic return to the previous show failed as well. capacity.md · NVIDIA L4 has every run, the 10-bit modes and what was derived instead of tested.

A profile and a preset switch it on for an instance. The opt-in nvidia_l4_cuarray instance profile generates SDR and HLG 4:2:0 clips as HEVC with fixed pools of 12 extra frames and keeps that across Setup changes of frame rate and canvas format; it admits 192 sources at 25 fps on an SDR canvas. The portable L4 preset builds the pinned FFmpeg series and selects that profile. The nvidia_l4 and tesla_t4 profiles keep linear decoding and FFmpeg 8.1.

Earlier savings already in the baseline

One decoder thread. GPU video sources use decoder options.threads=1. FFmpeg frame threading otherwise reserves additional decode surfaces per active frame thread while NVDEC does the decode work. This is separate from one thread per GPU filter graph, and does not impose a one-thread policy on CPU decoding.

Low-DPB demo assets. Generated H264/HEVC demo clips use -bf 0 -dpb_size 2 to reduce reference-picture requirements at the source. Each clip remains an independent full-resolution input processed every frame. This changes the encoded media and can trade compression efficiency for a smaller decode footprint; it cannot remove reference pictures that an incoming live bitstream requires.

Both optimizations were already present in the 20.65 GiB linear baseline. Their savings are not counted again in the CUarray result.

At a glance

  • WhatOpt-in upstream FFmpeg NVDEC output into registered CUDA arrays, with fixed pools and direct compositor texture reads. The existing decoder node and AVP API stay in use.
  • WhyRemove separate decoded-image storage and its copy, while keeping the queues that absorb normal scheduling variation.
  • LatencyDecoded queue: three frames. AUX deadline: 80 ms. Matched 20-output cut p95 was 96.5 ms versus 99.4 ms on FFmpeg 8.1; at 28 outputs it was 111.2 ms.
  • CostEach decoder has a private producer stream. Consumer events order GPU reads, and frame references stay alive until reads finish. Fixed surface budgets must cover the whole graph.
  • RiskAn undersized pool causes decode errors, not automatic growth. CUarray requires compatible filters and the pinned development build. Matching scale_cuda passes through; array scaling or format conversion is rejected.
  • Validation limitsActual HEVC 10-bit 4:2:2 decoding still needs Blackwell; P210 array sampling passed synthetic GPU tests on L4. Replay seeking and sequence changes remain separate milestones. An idle compositor can retain its former scene's pool until its next draw or destruction.
  • Switch it offSet the video source's decode_storage to cuda to use linear CUDA again. The default build remains FFmpeg 8.1. CUarray has no hidden CPU/copy fallback and disables decoder auto-restart to avoid overlapping replacement pools.

Use the measured configuration
