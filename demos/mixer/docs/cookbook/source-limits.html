Current workload limits and evidence

Separate long historical capacity runs, profile admission limits and the latest short moving-browser transition checks.

Reviewed 15 October 2026 against e72ff8b4. These pages describe that code and named workload settings; they do not assert what every deployment runs.

Moving browser workload · 15 October 2026

12-vCPU NVIDIA L4; 1080p HLG 4:2:0; 57 video inputs; 18 encoded outputs. Counts include four cropped DSKs; every other browser page is animated at 1920×1080 and the canvas rate. Fixed prewarmed pool nine, one CUDA copy per browser frame, 32 compute/eight copy connections and L4 frame staggering enabled. Each row covers four transitions between two 32-layer grids: one-second fades/cuts six seconds apart.

fps Windows / workers AUX preset Browser repeats / skips Key repeats / skips
25 40 / 4 × 10 p3 0 / 0 0 / 0
30 40 / 4 × 10 p3 0 / 1 0 / 0
50 40 / 4 × 10 p3 0–3 / 0–3 0 / 0
60 30 / 3 × 10 p1 3 / 3 0 / 0

Main presets: SDR p5, HDR p3, clean p3. AUX p1 is a quality/throughput tradeoff. These runs had no compositor misses or new imports. A second recorded four-fade pass at 50 fps had zero observed browser/key repeats or drops; at 60 fps it had one browser repeat/drop and two skipped key frames. Encoded recordings had regular RTP cadence and changing sampled ticker, corner and grid regions.

These are short smoke results, not zero-drop guarantees. They do not qualify 64-layer transitions. At 60 fps, 32 windows repeated hundreds of frames and 36/40 collapsed into persistent repeats. Eleven buffers did not rescue 32 windows. Three larger worker groups failed the 40-window/50-fps case; grouping is part of the result.

Historical capacity and admission

The earlier 16-vCPU L4 192-source SDR30 show used 105 NVDEC, 40 mostly still browser and 47 raw inputs, with 24 outputs. It ran 40 minutes with no Program/AUX deadline miss or AUX drop. That workload is different from the moving-page transition checks above. Other format/rate rows in the profile are admission limits unless explicitly measured.

The maintained capacity reference retains those distinctions and GPU-specific tables. Do not extrapolate L4 numbers to T4, or treat a successful code/pixel test as a new capacity benchmark.

Configuration is not deployment state

The reviewed branch includes these implementations and L4 defaults. Stock Chromium plus shim remains the ordinary browser installation; the fixed-pool test used the optional patched exporter. This page does not assert that a public demo or a different host is running that build. Check its actual images, recipe, environment and reported pool before comparing results.
