Browser frame hand-off

Each browser window passes its painted frames to the mixer as DMA-BUF descriptors over a Unix socket, and the mixer acks every frame back. The sender's socket thread now sleeps in poll() instead of waking every millisecond, a vanished socket file is re-bound, and a failed page reloads without dropping the mixer's connection.

Status: Implemented, deployed on the test host

Browser wake-ups fell by about 35,000 a second, consistent with 1000 a second for each of the 40 windows. Even so, the table measures everything that changed between the two images, not the poll() rewrite alone. The 5 ms cut-latency difference is within run-to-run noise.

What changed

  1. The socket thread waits in poll(). Before, each window's accept thread tried accept(), read acks from every client, then slept 1 ms: about 1000 wake-ups a second per window. Now it blocks in poll() on an eventfd (stop, re-bind, client removal), the listening socket and every client, and reads each ack as it arrives. Acks are read before new connections are accepted, so a reused descriptor number is never taken for the old client. A descriptor already removed is ignored. A persistent error pauses 1 ms, so poll() cannot spin.
  2. A vanished socket file is re-bound. The 1 s socket monitor notices the missing file and calls createServer, which binds a new socket and moves it under the old descriptor with dup3, so connected consumers keep their frames. If that fails, the file is unlinked, since nothing listens behind it, and the next check retries. Before, createServer returned early and the file stayed gone.
  3. Failed pages reload; the capture channel stays. A main-frame load failure, a load past the watchdog (30 s by default) or a renderer crash reloads the page after 1 s, doubling up to 30 s while reloads keep failing, and logs each attempt to stderr. Sub-frame failures and ERR_ABORTED (a cancelled or superseded navigation) are ignored. The consumer keeps its connection and the frames it holds. Before, any did-fail-load tore the window down: the socket closed, the mixer quarantined its frames, and a failed re-create left the source frozen for good with no alarm. A renderer crash had no handler at all.
  4. Type-aware lint. @typescript-eslint/no-floating-promises now runs with ignoreVoid: false: void promise no longer passes, so every fire-and-forget call ends in .catch(). Also added: return-await (only inside try), switch-exhaustiveness-check and no-unnecessary-condition; the lint script reports stale disable comments. Following its findings turned up two bugs. Media elements bound before the first audio collector was ready each built their own, so an element could stay silent and uncaptured; they now share one setup. And a crash restart queued before stop() respawned the stopped worker, which kept holding its port.
  5. Per-window ring size. The setup's browser_ring_size (6 at 25 fps), sent as each window's ringSize, now sizes that window's frame pool. Without it, the process-wide DMA_BROWSER_DMABUF_POOL_SIZE applies (default 11).

At a glance

  • WhatBrowser sender changes only, in deps/dma-browser: the fd-passing thread waits in poll(), a vanished capture socket is re-bound, failed loads and renderer crashes reload the page, stricter lint and the bugs it found, and a per-window ring size. avplumber is unchanged.
  • WhyWith 40 windows, the 1 ms loop alone meant about 40,000 wake-ups a second, most of them finding nothing. A page that failed to load, or whose renderer crashed, froze its source with no alarm.
  • Latency0 frames added to program and to command-to-screen: no queue, buffer or node changes. Acks are read as they arrive instead of at the next 1 ms tick, so each frame returns to the browser's pool up to 1 ms sooner. Median cut latency measured 70 ms old and 75 ms new, within run-to-run noise.
  • Side effectsWhile a page is down, Chromium paints its own empty error page, so the source shows transparent or black instead of holding its last frame. The source recovers on the next successful reload. Sub-frame failures and ERR_ABORTED are now only logged.
  • Cost0 nodes, 0 queues, 0 VRAM: browser processes held 1,272 MiB before and 1,265 MiB after. One eventfd per window; each wake-up rebuilds the pollfd list of the eventfd, the listener and the window's clients. Code: +51/−28 lines in the fd-passing addon, and a 57-line page reloader with tests.
  • RiskLow. The poll() loop's hazards are covered: acks are read before accept(), removed descriptors are skipped, removeClient() calls wake() because close() does not end a poll(), and a persistent error pauses 1 ms. A URL that never loads retries every 30 s indefinitely, logged each time.
  • Switch it offNo runtime switch. Revert the commits and rebuild the browser image; avplumber needs no change.
