Skip redundant colour-tag nodes

Reviewed 2026-10-06 against mixer-improv at d1dc35fa. Measurements retain their original workload and validation scope; this review does not certify a running deployment.

Already-tagged raw YUV inputs can bypass a standalone metadata-only colour filter. Real conversion and alpha handling stay in the graph.

build_raw420_input(color=...) stamps tags inside its existing upload filter. The v210 builder also stamps the declared tags. MixerSource.color_tagged defaults to false and is an explicit promise that every upstream frame carries the declared YUV colour tags.

The graph bypasses a colour node only when the generated graph equals that source's setparams expression exactly. A differing colour space, tone map, format conversion or alpha treatment prevents this shortcut. Packed RGB cannot make the YUV promise.

The application enables this automatically only for raw NV12/P010/v210 sources with neither a user filter nor a process_source callback. A configured geometry transform preserves frame properties. Video and browser colour nodes are not automatically removed.

188-source saving

The captured matched-SDR configuration has 32 eligible raw inputs: 32 nodes and 32 queues saved. Together with removing 152 input FPS nodes, that is 184 nodes and queues. Applying only these two changes to the old 1,514-node capture yields 1,330. This is arithmetic from that configuration, not a recount of a deployed graph; routing or wipe changes can change the total independently.

GUI startup accepts a running source fan-out when its colour filter was legitimately bypassed; an existing but stopped colour filter still fails readiness.

Validation scope

The change includes graph-contract tests and byte-exact colour-tag assertions. The earlier mixed-rate GPU report predates this commit, so it does not qualify the bypass. A new full-show performance result is not claimed.
