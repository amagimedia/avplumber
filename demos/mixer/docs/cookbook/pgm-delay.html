PGM delay instead of a longer aux deadline

The Program preview aux keeps the normal 80 ms deadline for all its sources and shows only its PGM pad one frame back, because the finished program arrives a frame later than the sources it is made of.

Status: Implemented, not deployed

The timing

Every compositor draws output time T at T + 80 ms (a 2-frame playout deadline at 25 fps). An input that misses the deadline repeats its last frame; nothing stalls. The Program preview aux (layout pgm_pvw_grid: 100 source pads + 1 PGM pad) also takes the finished program. That leaves the M/E at about T + 2 frames + keyer ≈ T + 96 ms, after the deadline.

At a glance

  • WhatOne integer parameter, pgm_delay_frames: 1, on the Program preview compositor aux_mv_comp. It applies to the last input only, the program feed aux_mv_pgm: output tick T takes PGM T−1. The other 100 inputs keep the normal 2 frames.
  • WhyThe old fix raised the whole aux to 120 ms (3 frames). Measured live: aux_mv_comp latency_ms = 120, aux_mv2_comp = 80, M/E at the default 2 frames. All 101 inputs waited a frame to help one.
  • Latency

    Program output: unchanged. This is a monitor.

    Program preview aux: source and PVW tiles 120 → 80 ms (−1 frame, −40 ms). PGM tile: 120 ms, unchanged.

    Command-to-screen on this monitor: a cut reaches the PGM tile as before; changes on the other tiles show one frame (40 ms) sooner, because tick T is drawn at T + 80 instead of T + 120 (derived from the deadline, not measured).

  • Side effectsThe PGM tile shows one tick older than the tiles beside it, so PVW and PGM are no longer the same instant. The aux now has the same deadline as every other compositor. The Source pages layout does not use the parameter.
  • Cost0 nodes, 0 queues, 0 threads, about 20 lines. The offset moves a queue slot index; no extra draw work. VRAM: frees the extra frame that all 101 inputs held, ~105 MB (up to 216 MB).
  • RiskThe program keeps the old margin: PGM T must arrive by T + 120 ms, as before. If it is late, the PGM tile repeats its last frame; nothing stalls. Latency plus offset must fit the six-frame history budget (240 ms at 25 fps), so the aux accepts 40 ms less main latency. The parameter is rejected on a compositor driven by clock_input.
  • Switch it offDrop the parameter (AuxMultiview.pgm_delay_frames = 0) and add back +1 frame of latency on that aux (latency_ms 120 at 25 fps).
